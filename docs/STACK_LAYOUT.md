# 위성 상태 개요의 부품 배치와 계측 연결

고정 CAD 상태 화면은 [배치 설정 예시](../config/equipment-layout.example.json)의
BODY 좌표와 부품별 TM 연결을 사용한다. 장치의 온도·전압·상태는 수신하고 파싱한
자료에서 가져오며, CAD 그림 자체가 계측값이나 센서의 실측 위치를 제공하지 않는다.

## 화면과 데이터 흐름

ROS 첫 번째 종합 탭에서 왼쪽의 장비별 계측 표와 오른쪽의 고정 CAD를 함께 확인한다.
장비 이름이나 CAD 연결선 상자를 선택하면 대응하는 장비를 강조한다. 기존 회전 가능한
자세 화면과 센서 그래프·이력은 그대로 사용할 수 있다. 좁은 화면에서는 두 패널을
세로로 배치한다.

인증된 `/api/ros/equipment-status` 요청은 기존 포털→ROS 내부 API를 통해
수신 TM 보관소를 읽는다. 패킷 원문·CRC와 파싱 값이 일치하는 자료만 사용하며,
전체 HK는 분할 수신이 끝난 레코드만 반영한다. 새 포트나 외부 접속은 추가하지 않는다.
화면은 기존 5초 갱신 주기에 연결되어 있다.

표의 각 값은 측정 UTC, 수신 시각, 최신성, 허용 범위를 보유한다. 늦게 수신한 과거
TM이 최신 측정값을 덮어쓰지 않는다. 오래된 값과 자료 없음, 범위 미설정, 한계 초과를
구분한다. 녹색 범위 판정은 해당 단위의 한계가 설정되고 최신 값이 그 안에 있을 때만
사용한다. 센서 한계는 기존 ROS 센서 설정에서 수정한다.

## 사용한 스택 자료

- 파일: `PADO-SAT_3D스택_IFB_261026(배포용).html`
- SHA-256: `b88a73774af8c0730217b60e77918a46e8e59e225241eafe8dd3e0fd5986cd8c`
- 자료 개정: `261026`, 사용한 안: `p2`(제공 HTML의 초기 선택)
- 단위: mm. 원문은 보드 높이와 치수가 근사치이며 ±X·±Y 방향은 STR CAD에서
  확인해야 한다고 명시한다. 이 설정은 확정된 비행 배치도가 아니다.
- HTML에 포함된 JavaScript와 3D 라이브러리를 실행하거나 웹 서비스로 복사하지
  않고, 장치 목록·높이·스택 순서의 리터럴 자료만 읽었다.

`p2`의 +Z→−Z 순서는 다음과 같다.

`CREST → DMC-3 → CubeADCS → P60 → IFB → SatNOGS → BPX → SIREN → UHF 안테나`

배치 계산은 원문의 `layout()`과 같은 중심 정렬을 사용한다. 초기
`explode=0.35`는 장치를 벌려 보여주는 화면 효과이므로 제외하고,
`explode=0`일 때의 보드 간격 3 mm를 사용했다. 높이 합계 277 mm와
간격 24 mm를 합한 compact 스택 높이는 301 mm다.

## BODY 좌표와 연결선의 의미

스택 HTML의 렌더 Y축은 CREST 쪽 위성 +Z에 해당한다. 화면 설정은 다음
오른손 변환을 기록한다.

```text
BODY X = STACK X
BODY Y = −STACK Z
BODY Z = STACK Y
```

X·Y 면 방향은 원문에서도 미확정이므로 이 대응은 임시다. 현재 연결선의
시작점은 모두 스택 중심선의 보드 중심이며, X=Y=0이어서 이 면 부호 가정의
영향을 받지 않는다. 정확한 센서 장착 위치를 나타내는 점으로 해석하지 않는다.

| 장치 또는 호스트 | 중심 BODY Z (mm) | 현재 위치 정보 |
|---|---:|---|
| CREST | 103.0 | 근사 장치 중심 |
| DMC-3의 A3200·AX100·OEM719A | 41.5 | 같은 호스트 중심을 공유. 개별 모듈의 횡방향 위치 미정 |
| CubeADCS | 5.0 | 근사 장치 중심 |
| P60·ACU·PDU 1·PDU 2 | −32.5 | 같은 호스트 중심을 공유. PDU 번호와 X2/X3 대응 미정 |
| IFB | −52.5 | 근사 보드 중심 |
| SatNOGS COMMS | −68.5 | 근사 보드 중심 |
| BPX | −100.5 | 근사 장치 중심 |
| SIREN | −132.5 | 근사 장치 중심 |
| UHF 안테나 | −147.0 | 근사 장치 중심 |

기존 자세 화면의 [CAD 메시](../web/assets/pado-sat-deployed-mesh.json)는 BODY XYZ와
mm 단위를 사용한다. 스택 배치를 바꾸어도 외부 CAD 형상이 자동으로 바뀌지는
않는다. CAD가 개정되면 [CAD 변환·축 안내](ROS_CAD_자세_뷰어.md)에 따라 메시도
교체하고 중심·축 대응을 다시 확인한다.

## 계측 연결과 미정 장치

각 `equipment[].readings[]`는 다음 정보를 담는다.

- `id`, `label`, `unit`, `kind`, `decimals`: 화면 표기
- `tm.packet`, `tm.field`: 현재 파싱된 계측 패킷의 스칼라 필드
- `full_hk_path`: 전체 HK에서 읽을 절대 키 경로. 배열 인덱스는 정수로 기록
- `sensor_limit_key`: 기존 공통 설정의 센서 허용 범위 키(정의된 항목만)
- `max_age_s=120`, `full_hk_max_age_s=1200`: 표시용 최신성 기본 기준
- 장치의 `anchor_body_mm`, `anchor_kind`, `callout`: 위치와 연결선 표시 순서

GNSS 수신기의 온도·전압은 이름이 명확한 `HWMONITOR` 시험 HK에서만 연결한다.
CubeADCS의 의미가 확정되지 않은 혼합 계측 배열을 임의로 온도나 전압으로
해석하지 않는다. 단위·TM·한계가 정의되지 않은 항목은 값을 만들어 정상으로
표시하지 않는다. 일반 계측과 전체 HK는 측정·수신 시각과 최신성을 따로 확인한다.

PDU의 `bus_voltage_v`는 조정된 공통 버스 전압이고, 전체 HK의 `v_out[0]`는
각 PDU의 첫 출력 채널 전압이다. GNSS용 3.3 V와 S-band용 12 V처럼 서로
다른 레일을 가리키므로 두 값을 같은 전압의 대체 자료로 합치지 않는다.
PDU 1의 전체 HK 온도도 현재 시뮬레이터에서 스칼라 온도와 별도로 생성되므로
스칼라 온도의 대체값으로 연결하지 않는다. 이 세 항목은 지정된 스칼라 TM만
사용한다. 개별 출력 채널의 전압·전류·온도는 센서 의미와 장착 위치가 확인되면
별도 계측 항목으로 추가한다.

새 스택의 IFB·SatNOGS와 안테나 개별 계측은 아직 연결하지 않았다. 특히 기존
시뮬레이터의 `SRS_4` 값을 SatNOGS 상태로 바꾸어 표시하지 않는다. 원문의 SIREN
전원 등 변경 사항도 시뮬레이터의 전력 모델이나 TC/TM 규격에 자동 반영하지
않는다. 이 설정의 역할은 화면 위치와 계측 연결뿐이다.

## 스택 변경 시 갱신

소규모 변경은 검증 환경의 `config/equipment-layout.json`, 운용 환경의
`config/operations/equipment-layout.json`에서 부품 위치·연결선을 수정한다.
각 환경의 `spacecraft.json`과 같은 디렉터리이며, 실제 설정은 Git에 포함하지 않는다.
해당 파일이 없으면 이미지에 포함된 예시 설정을 사용한다. 현재
소프트웨어가 읽는 패킷 필드·전체 HK 키·센서 한계 키와 맞게 수정해야 한다.

```sh
# 검증 환경에서 최초로 배치 설정을 분리할 때
cp config/equipment-layout.example.json config/equipment-layout.json
chmod 0644 config/equipment-layout.json
```

기존 설정 마운트를 사용하므로 화면 갱신 때 변경 내용을 다시 읽는다. JSON이 잘못되면
기본 배치로 조용히 바꾸지 않고 조회 오류를 표시한다. 개발 실행에서는
`PADO_EQUIPMENT_LAYOUT`으로 별도 경로를 지정할 수도 있다.

새 HTML을 받았을 때는 다음처럼 **별도 후보 파일**을 만든다.

```sh
python tools/extract_stack_layout.py /path/to/new-stack.html \
  --plan p2 --output out/equipment-layout.candidate.json
```

추출기는 알려진 `OBJ`·`ORDER` 리터럴, 높이·폭·깊이·compact 간격만 읽고
JavaScript를 실행하지 않는다. 형식이 달라지거나 값이 계산식이면 실패하고
원문 검토를 요구한다. 기존 파일을 덮어쓰지 않는다.

같은 호스트 장치의 계측 연결은 유지하고 바뀐 높이·순서에 따라 중심을 옮긴다.
새 장치는 `UNMAPPED`로 추가하며 이전 장치의 값을 대신 연결하지 않는다.
후보와 원문을 대조한 뒤 승인한 내용을 실제 설정 파일에 반영한다. 실제 센서
좌표가 준비되면 고유 장치/센서 ID와 확인된 BODY 위치로 연결점을 세분화한다.
소스 개정·SHA-256·좌표계와 위치 확인 수준도 함께 갱신한다.
