# 단계 9 ROS·MPS 화면 구조

2026-10-23 사용자와 합의한 화면 기준선이다. 세부 시각 디자인과 운용 동작은 후속 검토에서 다듬는다.

## ROS

| 화면 | 관제자가 확인하는 것 | 현재 연결 |
| --- | --- | --- |
| 종합 관제 | CAD 자세, 센서별 그래프·한계·이벤트·비콘, 두 지상국 AOS/LOS 예측 | 시험 TM 스냅샷·비콘·FDIR 아카이브와 FDS 자료 |
| 수신 TM | 수신 번호·종류 검색, RAW HEX·헤더·파싱 값·전체 HK 재조립 | 영속 SQLite 원문 아카이브, 인증된 읽기 전용 API |
| TC 준비·예약 | MPS 시험 시퀀스의 단계·인자·AOS 기준 시각 오프셋 확인, 예약 상태·가상 위성 응답 확인 | 수동 파일 반입 `DRAFT_ONLY`와 별도 `SIM ONLY` 전달·예약·ACK 저장소 |

현재 상태와 이력은 분리한다. 게시된 시험 TM이 5분 이상 오래됐거나 새 입력을 확인할 수 없으면 최신 표본을 현재 정상/경보로 표시하지 않는다. 현황의 초과 센서를 선택하면 해당 TM 그래프로 이동한다. `SIM ONLY` 예약은 시각이 되면 가상 위성으로 초안 TC를 한 번 보내고 검증된 `COMMAND_RESULT` TM에 따라 상태를 표시한다. 실제 위성 TM, 운용 경보, 실제 TC 승인·인증·RF 송출은 연결되지 않는다.

PASS 카운트다운은 두 지상국의 FDS 시험 예측이며 RF 링크 실측이 아니다. N13과 ORBIT 시각이 다르거나 입력이 만료되거나 예측 구간 경계에서 PASS가 잘린 경우 확인 불가로 표시한다.

시험용 수신기는 그래프에 설정된 센서의 TM 표본을 최근 UTC 60분·PDU 계열별 최대 721개로 제한해 보관한다. 따라서 화면의 5분·30분·1시간 범위는 실제로 들어온 표본이 있는 구간만 표시한다. 시작 직후에는 이력이 쌓인 만큼만 보이고 수신 프로세스 재시작 후에는 새 표본부터 다시 쌓인다. 게시 스냅샷은 기존 1 MiB 상한을 유지하며 장기 운용 이력 저장소가 아니다.

## MPS

한 화면에서 `01 PASS 선택 → 02 시험 TC 후보 구성 → 03 계획 검토` 순서로 작업한다. 1단계는 검증된 FDS N13 일정의 두 지상국 PASS를 모두 보여준다. 현재 PDR 기반 TC 초안은 UHF 범위이므로 2단계는 **연세대 UHF PASS에서만** 초안 명령의 이름·순서·인자·AOS 기준 시각 오프셋 편집을 허용한다. 대전 S-band PASS는 조회 전용이며 서버도 후보 저장을 거부한다. 3단계는 PASS 경계, 저장 리비전과 각 단계의 인자·오프셋을 확인한다. 저장된 미래 PASS의 읽기 전용 시험 시퀀스는 명시적인 `ROS 시험 초안으로 전달` 동작으로만 ROS에 넘어간다.

MPS의 초안 시각은 절대 시각이 아니라 PASS AOS로부터의 오프셋이다. 전달·예약 때 일정 해시·리비전을 다시 확인하고, ROS는 PASS 안의 미래 시각에만 `SIM ONLY` 예약을 만든다. 이 흐름은 사용자가 전달과 예약을 각각 선택해야 시작된다. 충돌 판정, 운용 승인·출력과 실제 위성 명령 전송은 실제 CS/CDHS ICD 및 위성개발팀과의 정책 검토 뒤 별도로 연결한다.

MPS 계획 검토 하단에는 ROS의 검증된 가상 위성 ACK 최근 항목과 EPS 시험 SOH 값을 읽기 전용으로 표시한다. 오래되거나 손상된 TM은 정상으로 표시하지 않는다. Portal의 인증된 고정 API 조회이며, 운용 N10 SFTP 파일쌍·수신 ACK를 대신하지 않는다([시험 계약](../interfaces/n10/test_feedback.md)).

## 시험용 TC 왕복 상태

`MPS 저장 시퀀스 → 포털 재검증 → ROS SIM ONLY 예약 → 비공개 Unix socket → sim-ground → Docker 내부 TCP 9200 → sim-satellite → COMMAND_RESULT TM → ROS 예약 상태` 순서다. `mm_get_mode`, `hk_get` 등 허용된 조회 초안 명령을 사용하며 호스트에 추가 포트를 열지 않는다. 예약이 30초 이상 늦거나 PASS가 종료되면 `MISSED`, 재시작 중 송신 결과가 불명확하면 `UNKNOWN`으로 남는다. `ACKED`·`REJECTED`·`TIMEOUT`·`SEND_FAILED`를 화면에서 구분하고 자동 재송신하지 않는다. 수동 파일 반입의 `DRAFT_ONLY` 예약에는 이 dispatcher가 접근하지 않는다. 자세한 실행 경계는 [로컬 스택 안내](../deploy/stage9/README.md)를 참조한다.

TC 탭의 `가상 위성 저장 TM 수신`에서는 비콘의 수신 시각·순번·주기를 확인하고 `저장 TM 요청`을 즉시 보낼 수 있다. 이 요청은 MPS 일정 정보를 만들어내지 않고 별도 기록에 저장한다. `hk_dump`의 수락 ACK 뒤에 요청 시점의 저장 TM이 내려오며, 이후 새 표본은 다음 요청까지 저장된다. 비콘 수신만으로 계측 그래프를 갱신하지 않는다. ACK와 TM 수신 완료를 구별하며, 상세 계약은 [가상 위성 TC·TM 안내](SIM_TC_TM.md)를 참조한다.

## 후속 화면 검토 항목

- 실제 관제 모니터 해상도에서 밀도·스크롤·키보드 동선을 확인한다.
- 센서 ICD가 확정되면 그룹·단위·보정·한계의 표시 규칙과 다중 그래프 구성을 정한다.
- 추가 CAD·장비 실제 자료가 제공되면 현재 모델·파서 어댑터를 갱신한다.
- TC 승인·ACK 규격이 확정되면 시험 초안과 운용 화면의 상태 전이를 별도로 설계한다.
