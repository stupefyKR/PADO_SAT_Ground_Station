# 시뮬레이터 비콘·장비 TM·수신 화면

사용자가 제공한 LEOP 비콘 설계(70/129), 운용모드별 Beacon 데이터 항목(67/129),
Housekeeping 파라미터 총합(47/102)을 기준으로 장비 그룹과 항목 이름을 반영했다.
실제 장비 바이트 배열·보정식·단위·프레임 오프셋은 원본 데이터가 제공되면 연결한다.

## 비콘과 TC 요청

정상 HK 시험 비콘은 기본 10초 주기이며 `--beacon-period-seconds`로 변경한다.
기본 전력 모드는 `Standby`이며 설정한 모드가 비콘에도 반영된다.
10초는 시험 기본값이며 운용 HK 주기를 확정하지 않는다.

| 패킷 | 내용 |
| --- | --- |
| `BEACON_CORE` | 모드·비콘 횟수·주기·부팅·저장소·FDIR 요약 |
| `BEACON_INFO` | 시뮬레이터 식별 문자열·제공된 프로젝트 이메일 |
| `MODE_BEACON` | EPS·ADCS·GNSS·OBC·AX100의 현재 상태 요약 |

세 PDU는 각각 200 B 이내다. 이 시험 묶음의 길이를 PDR의 단일 비콘 크기
178–192 B와 동일하다고 보지 않는다. 실제 호출부호는 아직 정하지 않았으며
식별 문자열은 시뮬레이터용이다.

LEOP P-P 식별 패턴은 별도 참고 프로파일로 남겼다. P1 1.1초, 간격 0.3초,
P2 1.1초, RF OFF 7.5초가 한 주기다. 정상 HK로 전환하는 조건은 미정이다.
현재 프로그램은 정상 HK 흐름을 시험하며, LEOP RF 파형을 생성하지 않는다.
설정과 원본 크기 참조값은 `interfaces/pado_packets/beacon_profiles.json`에 있다.

`hk_dump(start_utc_ms, end_utc_ms)`를 받으면 해당 UTC 구간의 저장분을 측정
시각·패킷 순서로 내린다. `0/0`은 요청 순간의 전체 저장분이다. 이후 새 표본은
다음 요청까지 보관한다. 비콘과 저장 TM은 별도 시각·순번 경계로 처리한다.

## 생성 항목

기본 계측 TM 14계열은 5초마다 생성한다. 전력·배터리는 입사각·식·장치 부하를
사용하는 상태 모델로 계산한다. 세부 설정과 검증 방법은 [전력 모델](SIM_EPS.md)에 있다.
GNSS와 −X Nadir 자세는 동일한 TLE truth 궤도를 사용한다.

| 그룹 | 저장 TM 및 전체 HK 항목 |
| --- | --- |
| P60 Dock | 전력 채널·전압·전류·배터리·온도·부팅·래치업·워치독·전개 상태 |
| PDU-200 1·2 | 출력 채널·전압·전류·온도·가동시간·부팅·워치독 |
| ACU-200 | 태양전지 6채널·MPPT·boost·DAC·온도·전력 |
| BPX | 배터리 전압·충방전 전류·히터·4개 온도·부팅 |
| CubeADCS | 상태·쿼터니안·각속도·계측·액추에이터·실행·오류 요약 |
| OEM719A | ECEF 위치·속도·측위 상태 및 명명된 시험 GNSS 로그 |
| A3200 | 리셋·부팅·실행 이미지·crash·CPU/RAM/NOR·워치독 |
| AX100 | 온도·RSSI·송수신 횟수/바이트·접속·부팅 |
| SRS-4 | 전원·온도·RF 상태·프레임·오류·워치독 요약 |
| CREST·SIREN | 현재 정의된 상태·전압·전류·온도·통신·이상 알림 |
| FDIR | 고장 수준·발생 노드·고장 코드·조치·복구 상태 |

전체 HK는 첫 표본과 이후 600초 간격으로 버전이 있는 `pado.sim-full-hk.v1` JSON
자료를 만들고 `FULL_HK_CHUNK`로 분할한다. 장비별 배열과 시뮬레이터 파라미터도
이 자료에 포함한다. 실제 2,034 B HK 레코드나 NovAtel 바이너리를 재현한 것은
아니다. 괄호의 수치가 바이트 수인지 항목 수인지 불명확한 장비 필드는 시험 모델의
배열로 구분한다. 원본 장비 자료가 오면 별도 어댑터에서 실제 형식을 해석한다.
S-band 탑재체 과학 데이터 수신은 이 변경에 포함하지 않는다.

## 모든 수신 자료의 보관

수신기는 비콘·명령 응답·계측 TM의 정확한 PDU와 파싱 값을
`received_tm.sqlite3`에 보관한다. 개별 파일 경로는 API 입력으로 받지 않는다.
조회는 인증된 Portal → ROS의 읽기 전용 경로다.

| API | 기능 |
| --- | --- |
| `GET /api/ros/received-tm?limit=50` | 최근 패킷, 종류 필터·이전 페이지 |
| `GET /api/ros/received-tm/10` | `TM0010` 원문 HEX·헤더·파라미터 |
| `GET /api/ros/tm-events?limit=30` | 정상 상태를 제외한 FDIR 이벤트 |

`TM0010`은 지상국 수신 기록 번호다. 위성 패킷 ID·순번·측정 시각·수신 시각은
따로 보관한다. 전체 HK 분할을 모두 받으면 레코드 CRC를 검사하고 전체 JSON도
조회한다. 원문 아카이브와 최근 1시간 그래프 이력은 구분한다.

각 TM은 지상국 SQLite의 영속 저장이 완료된 후 `PSR1 + SHA256(PDU)` 수신
확인을 보낸다. 위성은 확인된 PDU만 삭제한다. 이 확인은 Docker 내부 시험
전송 규칙이며 실제 위성 ICD에 새 명령을 추가하지 않는다. 연결이 끊기면 미확인
TM은 남고, 다음 요청으로 재전송한 동일 원문은 중복 보관하지 않는다.

지상국 아카이브는 현재 1 GiB 상한에서 기존 자료를 자동 삭제하지 않고 수신을
중단한다. 미확인 TM은 위성에 남는다. 위성 자체의 24시간 저장 한도를 넘긴
표본은 기존 보관 정책대로 가장 오래된 묶음을 삭제하고 로그를 남긴다.

## ROS 화면

1. **종합 관제:** CAD 자세·20개 시험 센서 그래프·현재 한계·과거 초과·FDIR 이벤트·비콘 상태.
2. **수신 TM:** 수신 번호/종류 조회, 패킷 선택, RAW HEX·헤더·파싱 값·전체 HK 복원 자료.
3. **TC 준비·예약:** MPS에서 쌓은 TC 시퀀스를 AOS 기준 공통 시각에 한 번 예약하고
   ACK 순서대로 송신한다. AOS 몇 초 후와 UTC 시작 시각, 각 TC의 응답을 확인한다.
   즉시 저장 TM 요청도 별도로 사용할 수 있다.

장비에서 출력한 실제 데이터가 추가되면 형식·단위·보정식을 확인하고 시험 모델과
구분해 연결한다. 화면의 한계값은 `full_test_limits.json`의 시험값이다.

## 센서 측정 시각

각 TM PDU의 `utc_ms`는 위성에서 표본을 생성한 측정 시각이다. 지상국은 이를
센서 이력의 `samples[].utc`와 아카이브의 `sampled_utc`로 보존하고, 지상국에
도착한 `received_utc`를 별도로 기록한다. 미교신 중 저장했다가 내려온 값의
시각을 수신 시각으로 덮어쓰지 않는다.

ROS의 센서 카드에는 마지막 측정 날짜·UTC 시각을 표시한다. 작은 추세 그래프와
상세 그래프의 X축은 UTC 시각이며, 표시 구간은 마지막 측정 시각을 기준으로 한다.
따라서 다음 PASS에서 과거 TM을 받아도 실제 측정 시간대의 그래프를 볼 수 있다.
상세 그래프에서 표본을 가리키거나 키보드로 선택하면 해당 표본의 정확한 측정
UTC와 값을 확인할 수 있다. 자정을 넘는 구간도 날짜와 함께 확인한다.

검증에서는 위성의 두 표본을 15분 뒤에 내려받아 센서 20개와 RAW 헤더의
측정 시각이 유지되고 수신 시각만 별도로 기록되는 것을 확인했다. 화면 시험은
자정 전후 UTC 눈금, 불규칙한 표본 간격의 마우스 선택, 키보드 선택과 갱신 시
이벤트 정리를 포함한다.
