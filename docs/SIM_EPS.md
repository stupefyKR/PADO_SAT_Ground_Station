# 가상 위성 전력·배터리 모델

가상 위성이 사용하는 TLE truth의 위치·태양 방향과 BODY→ITRF 자세를 받아
발전량, 장치 부하, 배터리 충방전을 5초 간격으로 계산한다. −X Nadir 자세를
유지하므로 태양전지판의 +X 면이 항상 태양을 향하는 것은 아니다.

## 반영한 사양

| 항목 | 값 |
| --- | --- |
| 배터리 | 100 Wh, BPX 4S-2P, 정격 14.4 V |
| 배터리 운용 전압 참고 범위 | 11.8–16.0 V |
| 배터리 팩 자체 소비전력 | 최대 6 W |
| DSP | 24셀, 셀당 2.32 V × 0.490 A = 1.1368 W |
| MSP | 4셀, 셀당 2.18 V × 0.420 A = 0.9156 W |
| 태양전지판 법선 | 모든 셀 BODY +X |
| 정면 입사 시 합계 | DSP 27.2832 W + MSP 3.6624 W = 30.9456 W |
| PDU 효율 보정 후 | 30.9456 × 0.8 = 24.75648 W |

용량·최대 소비전력·셀 정격·배치·효율은 사용자가 확인한 값을 사용한다.
기존 PDR 발표자료 27·61쪽과 별첨 55쪽의 배터리·결선 정보를 참고했다.
태양전지 결선은 DSP 12셀씩 두 뱅크(각 4S-3P), MSP 4셀(4S-1P)로 설정했다.
결선은 채널 전압·전류에 반영하며, 모든 셀의 전력은 합산한다. 서로 다른 패널의
출력 전압을 단순히 배터리 전압에 더하지 않는다.

## 계산 흐름

1. 자세 쿼터니안으로 +X 법선을 ITRF로 변환한다.
2. 법선과 위성→태양 방향의 내적을 구한다. 후면 입사 시 발전량은 0이다.
3. 지구에 의한 태양 원반 가림 비율을 계산한다. 본그림자·반그림자를 반영한다.
4. `셀 수 × 셀 전압 × 셀 전류 × max(0, cos 입사각) × 태양 노출 비율`을 합산한다.
5. 합계에 변환 효율 80%를 한 번 적용한다.
6. 모드별 장치 소비전력 합계를 차감한다. 여유 전력은 충전에, 부족분은 방전에 사용한다.
7. 저장 에너지(Wh)를 적분해 충전율을 계산하고, OCV–SOC 곡선과 내부저항으로
   부하에 따른 단자전압을 계산한다. 전류·전압 제한, 만충 시 발전 제한과
   방전 한계에서 공급하지 못한 부하도 따로 기록한다.

배터리 전류·전력의 양수는 충전, 음수는 방전이다. 충전과 방전 전류를 별도 양수
필드로도 제공한다. 배터리 내부 손실·충방전 효율은 PDU의 80%와 별도 항목이다.
태양전지 온도별 I–V 곡선, 열화, 패널 자체 가림은 아직 이 모델에 포함하지 않는다.

## 장치 소비전력

첨부한 모드별 최대 소비전력 표를 그대로 설정 파일에 보관한다.

| 모드 | 장치 소비전력 합계 | 주요 활성 장치 |
| --- | ---: | --- |
| Detumbling | 15.54 W | GNSS 수신기·안테나 OFF |
| Standby | 16.49 W | GNSS 포함 기본 장치 |
| Communication | 27.29 W | Standby + S-band 10.8 W |
| CREST | 18.99 W | Standby + CREST 2.5 W |
| SIREN | 20.99 W | Standby + SIREN 4.5 W |

이 표는 최대 전력 배분이다. 기본 설정은 보수적으로 팩의 최대 6 W를 계속
소비하는 것으로 계산한다. 실제 평균 전력과 히터 동작률을 확보하면
`battery_auxiliary`의 모드별 값을 변경한다. 6 W를 배터리 충전 전력으로 더하지 않는다.
Safehold 부하표는 별도 자료가 없어 현재 Standby 값을 사용한다.

기본 모드는 Standby다. UHF 교신이 시작되었다는 이유만으로 S-band를 켜거나
Communication 모드로 자동 전환하지 않는다. 탑재체·S-band는 해당 전력 모드를
선택했을 때 소비전력만 계산하며, 과학 데이터나 실제 RF 송신을 추가하지 않는다.

## 설정과 상태 유지

기본 설정: `services/sim_sat/power_profile.json`.

초기 충전율 70%, 내부저항 0.12 Ω, 충전 2 A·방전 4 A 제한, OCV 곡선,
충방전 효율·간단한 열 모델은 변경 가능한 시험값이다. 특히 16.0 V는 제공된
운용 범위를 이용한 모델 제한이며, 실제 BPX BMS 충전 종료 규격을 확정하지 않는다.

배터리 상태는 기존 위성 TM 저장 볼륨의 SQLite에 저장한다. 한 표본의 TM,
생성 시각과 배터리 상태를 같은 트랜잭션으로 저장하므로 재시작·재전송·비콘
발행으로 충방전이 중복 적분되지 않는다. 기존 대기 TM은 그대로 보존한다.
FDS 궤도 파일 갱신도 배터리를 초기 충전율로 되돌리지 않는다.

궤도 자료가 없는 긴 공백은 임의로 충방전을 추정하지 않고
`integration_quality=gap_not_integrated`, `unmodelled_seconds`로 기록한다.
설정의 물리 파라미터가 달라진 상태를 기존 상태에 조용히 섞지 않도록 프로파일
해시를 확인한다. 새 물리 프로파일을 시험할 때는 기존 저장소를 삭제하지 말고
별도 `--spool` 경로를 사용한다. 모드만 바꾸는 것은 같은 배터리 상태를 이어 쓴다.

## TM과 ROS 확인

| 자료 | 확인할 내용 |
| --- | --- |
| `EPS_POWER` (0x2015) | 충전율·저장 Wh·발전 W·소비 W·충방전 W·식 여부·전력 제한 |
| `EPS_P60`, `EPS_BPX` | 같은 모델의 배터리 전압·전류·온도 |
| `EPS_ACU` | DSP 2뱅크와 MSP 1뱅크의 입력 전압·전류, 미사용 채널 0 |
| `MODE_BEACON` | 같은 표본의 배터리·태양전지 상태 요약 |
| `FULL_HK_CHUNK` 복원 JSON | `power_budget`의 장치별 소비전력·전류·손실·적분 품질 |

ROS 종합 관제에는 배터리·전력 요약과 추세 그래프가 표시된다. 수신 TM 탭에서
`EPS_POWER` 또는 전체 HK를 선택하면 RAW와 파싱 값을 확인할 수 있다.
이 값은 수신한 TM에 한정된다. 미교신 중 계산된 저장 TM은 다음 PASS에서
`hk_dump`를 요청한 뒤 표시되며, 과거 표본을 현재 측정으로 표시하지 않는다.

## VM 업데이트와 모드 시험

```sh
cd ~/pado-gs
git pull --ff-only origin feat/fds-core
./pado-gs.sh start
./pado-gs.sh status
```

탑재체 전력 모드를 시험하려면 기존 배터리 상태를 유지한 채 실행 모드만 지정한다.

```sh
PADO_SIM_POWER_MODE=crest ./pado-gs.sh start
```

지원 값은 `detumbling`, `standby`, `communication`, `crest`, `siren`, `safehold`다.
다음 실행에서도 같은 모드를 유지하려면 쉘에서 환경변수를 export한다.
모드를 지정하지 않은 다음 실행은 Standby로 돌아온다.

−X Nadir 상태에서는 입사각과 식, 최대 소비전력 가정 때문에 궤도 평균 전력이
부족해 충전율이 내려갈 수 있다. 이는 에너지 수지 결과로 확인하며, 임의로
발전량을 올리거나 배터리 전압을 주기 함수로 만들어 상쇄하지 않는다.

## 검증 기록

2026-10-27 Linux 파일시스템에서 Python 회귀 시험 300개를 실행해 269개 통과,
31개는 Docker·빌드 산출물 등 환경 조건에 따라 제외됐다. 전력 모델 24개와
전력/TM 연동 8개 시험은 모두 통과했다. 정면·경사·후면 입사, 식·반그림자,
CC/CV·만충·저전압, 에너지 보존, 재시작·저장 실패 롤백을 포함한다.

실제 HTTP·Unix 소켓 통합 시험에서 MPS 예약 → ROS 자동 TC → 위성 ACK →
저장 TM 271개 → 영수증 확인과 RAW·파싱 보관 → 20개 센서 게시를 확인했다.
기존 전력 패킷이 없는 대기 TM도 먼저 보관·확인하고 새 전력 표본이 도착하면
정상 게시하는 호환 시험을 통과했다. VM Docker 배포와 브라우저 표시는 별도 확인이다.
