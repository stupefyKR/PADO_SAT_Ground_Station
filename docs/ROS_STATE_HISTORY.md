# ROS 위치·자세 이력

ROS 종합 관제의 위성 자세 화면에서 최근 72시간의 위치와 자세를 탐색한다.
위치는 GNSS와 FDS 자료를 사용하고, 자세는 수신한 AOCS 쿼터니안을 사용한다.
자세 TM이 없다는 이유로 Nadir 자세를 만들어 표시하지 않는다.

## 화면 사용

1. 시간 바를 이동해 보고 싶은 UTC 시각을 선택한다.
2. `재생`·`일시정지`와 배속을 사용해 이력을 따라간다.
3. `현재`를 누르면 현재 시각을 다시 따라간다.
4. 표시된 위치의 출처, 자세 상태, 측정 UTC와 수신 UTC를 확인한다.
5. 이전·다음 자세 TM 버튼으로 실제 수신 표본의 측정 시각에 바로 이동한다.

시간 바에는 자세 TM이 확보된 구간을 표시한다. 빈 구간에서는 위치를 알더라도
`자세 정보 없음 · 마지막 수신 자세 유지`를 표시하고 CAD와 기체 좌표축을 계속
보여준다. 선택 시각 이전의 마지막 유효 자세 TM을 표시용으로 유지하며, 자세
측정 UTC는 그 표본의 실제 시각이다. 이전 자세 TM도 없으면 기준 형상을 표시한다.
위치와 지구·태양 방향은 선택 시각의 자료를 계속 사용한다. 이력 바의 자세 확인
구간이나 실제 자세 판정은 표시용 자세 때문에 늘어나지 않는다.

태양의 상태는 `표시 중`·`시야 밖`·`지구에 가림`·`방향 자료 없음`으로 구분한다.
`태양 방향 보기`는 위성을 중심에 둔 채 카메라만 태양 쪽으로 돌린다. 지구 뒤의
태양은 가려진 상태를 유지하고, FDS 태양 방향 자료가 없으면 위치를 만들지 않는다.

## 측정값과 표시 상태

| 자료 | 표시 기준 |
| --- | --- |
| GNSS 위치 | 선택한 시각의 수신 위치를 우선 사용 |
| GNSS 사이 위치 | 유효한 두 표본의 간격이 120초 이내일 때 보간, 보간임을 표시 |
| FDS 위치 | GNSS로 연결할 수 없는 구간에서 기록된 예측값 사용, FDS 출처 표시 |
| 수신 자세 TM | 선택한 측정 시각의 쿼터니안 사용 |
| 자세 TM 사이 보간 | 같은 좌표계의 유효 표본 간격이 10초 이내일 때만 SLERP, 보간 표시 |
| 현재 시각의 최근 자세 | 10초 이내 표본은 실제 측정 시각·경과 초와 함께 표시 |
| 자세 정보 없음 | 이전 유효 TM의 자세로 형상만 유지, 없으면 기준 형상 표시. 실제 자세는 미확인 |

현재 정규화된 자세는 `[w, x, y, z]`, BODY→ITRF 회전이다. 위성의 자세 제어 모드가
Nadir인지는 표시기에서 가정하지 않는다. 실제 장비의 좌표계가 다르면 수신
어댑터에서 이 정규화 좌표계로 변환해야 한다.

기존 센서 추세 그래프는 최근 1시간 표시를 유지한다. 72시간 재생 바는 위치·자세
화면에 적용되며 ORBIT의 현재 위치 화면과 독립적으로 동작한다.

## 늦게 내려온 TM

TM의 `utc_ms`는 위성 측정 시각이고, `received_utc`는 지상국 수신 시각이다.
수신기는 72시간 이내 저장 TM을 기존 교신 경계에서 수신·검증하고 원문을 보관한다.
오래된 GNSS를 현재 GNSS 입력으로 FDS에 다시 보내지는 않는다.

이력 조회는 수신 기록 ID를 증가시키며 새 자료를 가져오고, 화면에는 측정 시각으로
배치한다. 따라서 오늘 받은 어제 자세 TM은 오늘 자세를 대신하지 않고 어제의
빈 구간을 채운다. 사용자가 과거 시각을 선택해 둔 동안에도 새 자료를 반영하며,
선택 시각을 현재로 강제로 이동하지 않는다.

예를 들어 이틀 전 위치만 알고 자세를 몰랐던 경우, 해당 측정 시각의 자세 TM을
받으면 같은 시각으로 돌아가 수신한 자세를 확인할 수 있다. 다른 긴 미수신 구간은
계속 `자세 정보 없음`으로 남으며 해당 시각 이전의 마지막 수신 자세로 형상을 유지한다.

## 저장과 API

- TM: 기존 `received_tm.sqlite3`의 원문과 측정·수신 시각을 읽기 전용으로 조회한다.
- FDS: 게시할 때 `orbit_history.sqlite3`에 위치·태양 방향·입력 epoch·출처를 기록한다.
  최근 72시간의 과거 예측과 현재 예측 범위를 유지한다.
- `GET /api/ros/state-history`: 최근 72시간의 GNSS·자세 TM을 수신 ID로 나누어 조회한다.
  화면의 연속 갱신은 `follow=1`을 사용해 조회 중 새로 들어온 현재 표본을 건너뛰지 않는다.
- `GET /api/fds/orbit-history`: 같은 시간창의 FDS 위치 이력을 조회한다.

두 API 모두 기존 로그인 경계 안에 있다. ROS는 기존 TM 볼륨만 읽고, Portal은
기존 FDS 읽기 전용 볼륨을 사용한다. 새 외부 포트나 서브시스템 외부 접속은 추가하지 않는다.
페이지 크기·응답 크기·시간창을 제한하고, 잘못된 자세·위치 표본은 보간을 끊는
유효하지 않은 표본으로 전달한다.

기능 추가 이전에 받지 않았거나 저장하지 않은 자료를 소급 생성하지 않는다.
이미 보관된 TM은 최근 3일 범위에서 조회할 수 있고, FDS의 과거 예측 기록은
이 버전으로 게시한 시점부터 쌓인다. 가상 위성 자체의 저장 한도는 기존 24시간이며,
지상국이 이미 수신해 보관한 3일 이력과 구분한다.

## VM 반영

```sh
cd ~/pado-gs
git pull --ff-only origin feat/fds-core
./pado-gs.sh start
./pado-gs.sh status
```

FDS 최초 계산·게시가 끝나면 현재 위치와 새 위치 이력이 연결된다. 자세는 실제
수신한 TM에 따라 채워지므로, 비콘만 받고 저장 TM을 요청하지 않았다면 자세가
비어 있는 것이 정상이다. MPS 시퀀스 또는 ROS의 `저장 TM 요청`으로 수신한 뒤
측정 시각으로 이동해 확인한다.

## 검증

2026-10-29 Windows 회귀 시험 349개 중 308개가 통과했고 41개는 환경 조건으로
제외됐다. Linux 최신 집중 시험은 53개 중 51개 통과, 2개 환경 조건 제외다.
기존 MPS 예약 TC→TM 수신 통합 흐름도 유지됐다.

실제 수신기·HTTP API·브라우저 상태 해석을 연결한 시험에서는 이틀 전 GNSS만
있는 시점이 `UNKNOWN`이었다가, 같은 측정 시각의 비 Nadir 쿼터니안을 늦게 받으면
`MEASURED`로 바뀌는 것을 확인했다. 같은 과거 시각을 유지하며 긴 공백은 계속
`UNKNOWN`, 그 구간의 위치는 FDS 자료로 독립 표시된다. 보간·유효하지 않은 표본·
UTC·페이지 경계·동시 게시·재시작 후 읽기와 오프라인 미리보기 호환도 검사했다.
VM Docker 배포와 실제 브라우저 표시는 업데이트 후 확인한다.
