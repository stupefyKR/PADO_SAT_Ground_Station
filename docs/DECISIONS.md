## #36 단계 9 화면 구조와 이번 구현 범위

- 날짜: 2026-10-23
- 배경: 사용자는 ROS·MPS 화면의 큰 구조와 기능 동선을 먼저 정리하고 세부 디자인은 후속 작업으로 두기로 했다.
- 결정: ROS를 현황·경보, TM·자세, TC 준비·예약 탭으로 나눈다. MPS는 PASS 선택, 시험 TC 후보 구성, 계획 검토를 한 화면에서 순서대로 보여준다. 이번 변경은 기존 시험 기능과 상태 표시를 정리하며 명령 인자·실행 시각 저장, MPS→ROS 자동 전달은 포함하지 않는다. UHF TC 초안은 연세대 UHF PASS에서만 구성한다.
- 영향: 데이터가 오래되거나 조회되지 않을 때 현재 경보를 정상으로 표시하지 않는다. 대전 S-band PASS는 조회 전용이다. 실제 TC/TM ICD, 승인·송출 및 현장 배치는 별도 검증을 거친다. 화면 기준은 [STAGE9_UI.md](STAGE9_UI.md)에 둔다.

## #35 FDS는 궤도 예측 전용, ROS 시험 TM은 검증된 게시 파일로 읽기

- 날짜: 2026-10-23
- 배경: 사용자는 FDS에 궤도 기동 기능이 필요 없고 예측만 요구했다. ROS의 초안 TM 시각화는 수동 파일 열기만 제공했다.
- 결정: FDS 설정에 기동 입력을 받지 않고 산출물에 `maneuver_model=NONE`을 기록한다. 초안 UHF TM은 명시적 시험 한계표가 있을 때만 원자적 `TEST_ONLY_TM_SNAPSHOT`으로 게시한다. ROS API는 파일을 1 MiB 이하·엄격한 시험 계약으로 재검증해 인증된 포털의 읽기 요청에만 반환한다. 화면은 5초마다 갱신하고 5분 이상 지난 시험 표본을 오래된 자료로 표시한다.
- 영향: 수동 파일·합성 예시와 자동 게시 시험 화면은 운용 TM·경보·TC 경로와 분리된다. 실제 TM 스트림과 센서 DB는 CS/CDHS ICD 및 장비 시험 후 연결한다. FDS의 기동 모델이나 명령 API는 추가하지 않는다.

## #34 FDS 선행 입력에서 예비 질량·링크 버짓 제외

- 날짜: 2026-10-23
- 배경: PDR의 예비 질량과 링크 버짓 값은 비행 운용값이 아니며, 현재 중력장+태양/달 중력 전파에 질량은 쓰이지 않는다.
- 결정: FDS 설정의 필수 질량 항목을 제거한다. TC/TM 문서의 선행 입력에서 예비 질량·링크 버짓을 제외한다. PASS 경계는 구성한 고각 기준으로, Hz 도플러는 구성한 수신 주파수로 계산하며 시험 설정임을 표시한다. 거리 변화율은 주파수와 무관하다.
- 영향: 실제 안테나 컨택 검증에는 측량 좌표·고각 기준이, 실제 Hz 도플러 확정에는 할당 주파수가 필요하다. 항력·태양복사압을 정밀 모델에 추가할 때 질량·면적·계수를 다시 검토한다.

- 영향: receipt는 네트워크 전송 완료만 뜻하고 상대 애플리케이션의 파싱·수락 ACK가 아니다. 주소·계정·키와 실제 수신 ACK 방식이 정해지면 현장 통합 시험을 추가한다.

## #32 TC/TM 초안의 시험 연결 범위

- 결정: `docs/TC_TM/`을 검토 문서의 단일 위치로 둔다. 초안 GNSS PDU는 검증 후 **시험용** N11 파일 쌍으로만, 기타 초안 TM은 외부에서 명시한 **시험 한계표**가 있을 때만 ROS 시험 스냅샷으로 변환한다. MPS에는 초안 58종의 읽기 목록을 보여주되 필드가 정의된 36종의 이름과 순서만 PASS별 비운용 초안으로 저장한다. 운용 명령 DB·TC 게이트·승인 경로와 연결하지 않는다.
- 영향: 단위·센서 한계·RF/OBC 인증을 임의로 가정하지 않는다. 실제 패킷 및 장비 계약을 받으면 test-only 브리지를 승인된 수신 어댑터로 교체하고, CS/CDHS golden vector·FlatSat·현장 시험 후에만 운용 DB로 승격한다.

## #31 PDR 근거의 UHF TC/TM 응용 패킷 초안

- 날짜: 2026-10-23
- 배경: 사용자가 PDR 발표자료·별첨·제안서를 제공하고 CS/CDHS 자료를 토대로 지상국에서 TC/TM 패킷을 먼저 정의하도록 요청했다. 별첨에는 HK 필드 목록과 인증 요구가 있으나 비행 명령 번호·바이트 배치·인증 알고리즘·센서 보정/한계값은 없다.
- 결정: 기존 결정 #4의 빈 **운용** DB는 유지하고 `interfaces/pado_packets/`에 별도 비운용 제안 규격을 둔다. UHF 응용 PDU의 버전·ID·필드·길이·CRC 및 즉시/예약 명령을 명시하고 오프라인 코덱으로 검증한다. 패킷마다 초안 비트를 필수로 두고 200바이트를 넘기지 않는다. 실제 AX100 RF/CSP 프레임, 인증 및 TC 게이트와는 결합하지 않는다.
- 영향: FSW 함수 58개와 TM 16종을 목록화하되 인자 미정 22개 명령은 인코딩을 거부한다. 전체 HK는 불투명 레코드의 160바이트 청크 전송·재조립만 정의하고 내용 해석은 보류한다. GNSS_PVT의 ECEF 위치·속도는 검증 후 기존 FDS N11 형식으로 변환할 수 있지만 OEM719A 로그/실제 OBC TM 디코딩, N11 게시 및 운용 전환은 별도 검증이 필요하다. S-band payload 수신은 범위에서 제외한다.
- 후속: CS/CDHS가 후보 ID·필드·명령 인증·ACK·비콘/MTU 예산을 검토하고 Golden Vector 및 FlatSat 결과로 확정한 뒤 운용 DB와 ROS/MPS를 연결한다.

## #30 FDS 수신 파일의 원자적 입력 선택

- 날짜: 2026-10-23
- 배경: N05의 단발 인증 SFTP pull과 N11의 push 수신함, FDS 반복 계산기는 각각 존재했지만 검증된 수신 파일을 안전하게 현재 입력으로 교체하는 연결이 없었다.
- 결정: N05는 호스트 키 SHA-256 고정·키 인증을 수행하는 기존 C 클라이언트로 pull한다. N11은 별도 SFTP 수신함에서 매니페스트 완료 파일만 고른다. 경로·해시·유형·크기를 검증해 불변 스냅샷으로 저장하고, 현재 스냅샷 ID만 원자적으로 바꾼다. 손상된 최신 N11은 계산 경계를 차단하고, 일시적인 N05 접속 실패는 마지막 검증 입력을 유지하되 FDS 자체의 72시간 신선도 제한을 따른다.
- 영향: 파일 수신 경계는 실제 GNSS TM 디코더, N11 SFTP 서버 계정 설정, 실측 안테나 값, FDS 정밀도 수락을 대신하지 않는다. 실제 상대 연결은 최종 서비스·배포 과정에서 검증한다.

## #29 FDS N13 일정의 MPS 웹 읽기 경계

- 날짜: 2026-10-23
- 배경: FDS가 N13 파일 쌍을 생성하고 MPS C 파서가 이를 검증했지만, MPS 웹 API는 항상 빈 일정을 반환했다.
- 결정: FDS 실행별 N13 본문·manifest를 검증된 불변 디렉터리에 게시하고 `current.txt` 실행 ID만 원자적으로 바꾼다. 네트워크 없는 MPS C 읽기 컨테이너가 매 요청마다 파일 유형·크기·해시·CSV·지상국·시간창을 재검증한 뒤 Unix 소켓으로 API에 전달한다. 포털은 로그인·mTLS 경계를 거쳐 두 지상국 패스를 읽기 전용 표로 표시한다.
- 영향: 게시된 일정은 `operational: false`이며 ISS 화면의 고정 시험 파일과 분리한다. N13 변경·변조가 감지되면 503으로 실패한다. 패스별 후보 ID와 순서는 별도 비운용 SQLite 초안에 일정 해시·시간창·리비전과 묶어 저장한다. 실제 SFTP 수신/송신, TC 명령 카탈로그·파라미터, 충돌 판정·승인·출력은 별도 계약과 배포 작업이 필요하다.

## #28 ROS 시험 TM·자세 화면과 TC 예약 초안

- 날짜: 2026-10-23
- 배경: 사용자가 MPS TC 시퀀스 기반 ROS 구성·예약, TM 센서 시각화, 쿼터니안 자세 표시와 추후 CAD 형상 확장을 요청했다. 실제 TC/TM ICD와 자세 기준 좌표계, 운용 승인·충돌 정책은 아직 없다.
- 결정: 웹은 명시적인 시험 TM 정규화 파일 또는 합성 예시만 그래프·한계 초과·사각 기둥 자세 뷰로 표시한다. MPS `TEST_ONLY_SEQUENCE` 본문·매니페스트는 ROS API가 해시와 비운용 구조를 확인해 별도 초안 저장소에 넣고, 패스 시간창 내부의 단계별 예약 초안만 기록한다. 저장소에 실행 타이머·명령 인코더·signer·TC 게이트 연결은 두지 않는다. CAD 형상은 렌더러의 꼭짓점·면 공급 경계로만 준비한다.
- 영향: ROS 화면의 시험 한계 초과는 실제 경보가 아니며, 예약 초안은 승인·송출 의사가 아니다. 실제 TM 서버 파서와 품질·한계 이력, 자세 좌표계, TC 명령 DB, MPS 서비스 출력·독립 C 재검증·권한 증적이 확정될 때만 운용 흐름을 별도로 설계한다.

## #19 NAS 연동을 현 개발 범위에서 제외

- 날짜: 2026-10-23
- 배경: NAS 장비와 도입 시기가 정해지지 않았고, 사용자는 지상국 애플리케이션 개발을 먼저 완료한 뒤 필요할 때 연동하기로 했다. 이전 문서의 NAS 경로와 단계 8의 NAS 배포 수락 표현은 이 결정으로 대체한다.

- 영향: 단계 8의 선택 파일 스냅샷은 로컬 개발 시험 도구이며 전체 서버 상실에 대한 백업이 아니다. 운용 배포 수락에는 실제 데이터의 독립된 백업·복원 방안을 NAS와 무관하게 정하고 시험해야 한다. NAS 연동 여부와 방식은 그 뒤 별도로 결정한다. 원본 제안서와 이전 설계의 NAS 기술은 역사적 요구안이지 현재 구현 지시가 아니다.

## #16 운영 배포를 단일 VM·서브시스템별 Docker로 변경

- 날짜: 2026-10-23
- 배경: 사용자가 실제 운영도 Linux VM 한 대에서 Docker 컨테이너를 나누어 수행한다고 확정했다. 기존 개발방향의 VM 8대·VLAN별 방화벽·vm-mgmt 별도 VM은 실제 구축 구조와 맞지 않는다.
- 결정: 호스트 UFW는 VM 자체로 들어오는 트래픽을 제한하고, Docker의 내부 전용 브리지로 서브시스템 간 연결 쌍을 나눈다. 웹 UI 완성 전 공개 컨테이너 포트는 0개다. N2 연결 방향과 상대 신원은 실제 서비스 리스너·mTLS·SFTP 권한에서 따로 강제한다. 시간 동기는 VM 호스트를 사용하고 컨테이너 로그는 호스트 journald로 수집한다.
- 근거: Docker 문서는 공개 컨테이너 포트가 UFW 입력 규칙을 우회할 수 있다고 명시한다. 내부 전용 사용자 브리지는 공유하지 않는 컨테이너 쌍의 네트워크를 분리하지만, 같은 브리지 안에서 연결 시작 방향까지 제한하지 않는다.
- 영향: 이전 VM·VLAN·nftables 배포 조항은 대체한다. 단일 VM의 Docker 관리자와 호스트가 모든 서브시스템에 영향을 줄 수 있으므로 VM별 장애·침해 격리라는 이전 가정은 성립하지 않는다. 단계 7 probe는 배포 기반 검증이며 운용 서비스 배포 완료를 뜻하지 않는다. 외부 ICD·관리 PC·스토리지 연결은 확정 뒤 별도 승인 흐름으로 활성화한다.

- 이유: 외부 입력의 최대 크기를 제한하고, 미완료 파일이 수신처에서 처리되지 않게 하며, VM 통신 상대를 검증하기 위함이다.
- 영향: Linux에서 OpenSSL과 개발방향 11.1절의 libssh가 필요하다. 키·인증서는 실행 시 파일 경로로만 지정하고 저장소에 두지 않는다. 실제 VM의 IP·계정·호스트 키 값은 장비 확정 후 설정한다.
