# MPS 단계 4 시험용 계약

이 계약은 확정된 TC ICD가 없는 동안 MPS 계획 로직을 시험하기 위한 내부 C 모델이다. FDS가 생성하는 N13 Contact Schedule의 파일 형식은 현재 구현에 연결됐다. 실제 명령 코드, 자원 비트, 상태 비트, 전송률, 명령 수 제한을 정의하지 않는다. 이 모델의 결과는 운용 승인·TC 시퀀스 출력·송출에 사용할 수 없다. 아래 ROS 검증은 로컬 시험 파일 쌍에 한정한다.

## FDS N13 PASS 일정과 TC 후보 선택

- MPS는 `contact_schedule.csv` 또는 `contact_schedule-fds-*.csv`와 해당 `.manifest.json`의 바이트를 제한 크기로 읽어 스냅샷을 만든다. 매니페스트의 `CONTACT_SCHEDULE`, `fds → mps`, 버전 1, 실제 파일명과 SHA-256을 확인한 뒤 FDS `fds.contact-schedule.v1` 열을 해석한다. 두 지상국 `yonsei/UHF`, `kari/S_BAND`만 받는다. AOS·LOS·최고 고각 시각, 각도 범위, PASS ID 중복, 최대 72시간 범위를 확인한다. 밀리초 AOS는 초 단위로 내리고 LOS는 올려 기존 MPS 시간창 모델에 넣는다. 최고 고각·고각 마스크·예측창 잘림 표시는 함께 보관한다. 실제 SFTP 상대 인증은 단계 6 수신 경계의 책임이다.
- 각 PASS의 TC **후보 ID**를 순서대로 추가·교체·삭제할 수 있다. 결과는 FDS 일정 본문의 SHA-256과 PASS 시간창, 불변 리비전에 묶인다. 일정이 바뀌거나 오래된 리비전으로 수정하면 거부한다. 후보 ID는 임시 계획 표식이며 명령 DB의 실제 TC 코드로 해석하거나 ROS로 출력하지 않는다. 명령 파라미터·실행 시각·충돌 판단·승인·송출은 포함하지 않는다.
- 현재 저장소는 프로세스 메모리 모델이다. 실제 운영 DB 저장, 웹 편집 API, 권한과 인증 증적은 이후 MPS 서비스 통합에 필요하다. ISS 시험 산출물과 예시 안테나 값은 운용 스케줄로 사용하지 않는다.

## 초안과 버전

- 기존 4-2 시험 초안은 검증한 패스의 전체 시간창 스냅샷과 현재 비운용 명령 DB의 정수 `version`에 결합된다. 위의 새 TC 후보 선택은 별도 모델이며 FDS 일정 해시에 결합된다. 승인된 DB 해시 계약은 TC ICD 이후 별도로 정한다.
- 모든 초안과 분석 결과는 `non_operational`이며 명령 DB가 `operational: false`, `commands: []`일 때만 편집된다. 초안의 시험 명령 ID는 명령 DB의 실제 항목으로 해석하지 않는다.
- 한 저장소 인스턴스에는 계획 하나와 최대 32개의 불변 리비전, 리비전당 최대 64개 단계가 있다. `expected_revision`이 최신 리비전과 다르거나 패스 시간창·DB 버전이 바뀌면 수정을 거부한다. 저장은 현재 프로세스 메모리에만 적용한다. 영속 저장소·동시 프로세스 간 트랜잭션은 이후 서비스 통합 시 결정한다.
- 단계는 `offset_s`와 `step_id`로 정렬한다. 수정은 추가·교체·삭제이며 충돌이 있는 초안도 보존해 분석할 수 있다.

## 충돌 분석용 합성 속성

| 필드 | 시험 의미 |
|---|---|
| `offset_s`, `duration_s` | 패스 AOS 기준 실행 시작과 소요 초 |
| `resource_mask` | 같은 비트가 동시에 점유되면 자원 충돌 |
| `require_set`, `require_clear` | 앞선 명령들이 만든 상태에 대한 사전 조건 |
| `effect_set`, `effect_clear` | 해당 명령 후의 합성 상태 변화 |
| `uplink_bytes` | 가용 패스 시간의 합성 전송 용량과 비교할 바이트 수 |

분석 프로파일의 `initial_state`, `transfer_rate_bps`, `max_commands`는 시험자가 명시적으로 주입한다. `test_only=1`이 아니면 분석을 거부한다. 전송 용량은 `(LOS - AOS - 앞뒤 여유 시간) × 초당 비트 수 ÷ 8`의 내림값이다. 분석 결과는 여섯 규칙의 위반 비트 집합과 `non_operational=1`만 반환하며 승인 판정을 제공하지 않는다.

## 4-4 승인·시험 시퀀스·ROS 재검증

- MPS 승인 함수는 최신 리비전, 동일 패스 시간창·비운용 DB 버전, 충돌 없음, 별도 lead 승인자와 재인증 표시를 요구한다. 역할·재인증 값은 현재 시험 호출자가 제공한다. 실제 인증 증명이나 영속 승인 기록은 아직 없다.
- 출력 직전에도 최신 리비전, 패스·DB 버전 및 충돌 결과를 다시 확인한다. 이후 초안이 바뀌면 이전 승인 객체로 내보낼 수 없다. 출력 종류는 `TEST_ONLY_SEQUENCE`이며 파일명도 `TEST_ONLY_`로 시작해야 한다. `TC_SEQUENCE` 운용 출력은 제공하지 않는다.
- 시험 시퀀스는 패스·DB 정수 버전, 합성 단계·분석 프로파일, 작성자·승인자·승인 시각을 JSON으로 기록하고 SHA-256 매니페스트와 함께 게시한다. ROS의 별도 파서는 매니페스트의 송신자·수신자·해시·버전 및 JSON 스키마를 검사하고 신뢰한 패스·DB·프로파일과 시간창·상태·용량 조건을 다시 확인한다. 해시가 일치해도 합성 명령 규칙에 맞지 않으면 거부한다. ROS TC 큐나 송출 경로에는 넣지 않는다.
- 시험 코드는 파일 시스템의 파일 쌍을 검증한다. 장차 서비스 간 SFTP 받은 편지함에 연결할 때 수신 완료 후 불변 파일 보관과 전송 상대 인증을 결합해야 한다. 현재의 파일 재열기 구간은 원자적 스냅샷이 아니므로 신뢰 경계로 사용하지 않는다.

## 4-5 Mission Request·업링크 반입

- `SDC → DGS-Archive` 및 `DGS-Archive → MPS` 두 매니페스트가 동일 파일명·해시·버전·종류를 가리키고 각각 파일 해시와 일치해야 시험 반입을 등록한다. 실제 전송 상대의 인증 결과를 연결하는 서비스는 아직 없다.
- Mission Request의 내부 내용 형식이 확정되지 않아 바이트를 불투명하게 보관한다. 등록한 요청은 planner 역할의 반영 또는 반려 판정을 한 번만 받을 수 있다. 반영 직전 파일 해시를 다시 확인하고 현재 시험 초안 리비전을 참조할 뿐 명령을 자동 생성하지 않는다.
- 업링크 파일에는 두 단계의 출처 체인, 별도 입력 SHA-256, 목적, 버전, 제출자, 위험 여부 및 선택적 FlatSat 기록 ID를 보관한다. 다른 lead의 재인증 표시가 있어야 판정할 수 있고, 위험 파일 승인 시 FlatSat 확인과 기록 ID를 요구한다. 승인 직전 파일 해시를 재확인한다. 파일 내용은 실행하거나 TC에 연결하지 않는다.
- 역할, 재인증 및 FlatSat 확인은 시험 호출자의 주장이다. 실제 Portal 인증, 승인 증적, FlatSat 결과 연계, 임무 요청 스키마와 업링크 파일 정책은 해당 형식과 서비스가 정해질 때 별도로 연결해야 한다.
