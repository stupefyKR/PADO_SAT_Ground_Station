# MPS 단계 4-2·4-3 시험용 계약

이 계약은 확정된 TC ICD와 FDS Contact Schedule이 없는 동안 MPS 계획 로직을 시험하기 위한 내부 C 모델이다. 실제 명령 코드, 자원 비트, 상태 비트, 전송률, 명령 수 제한을 정의하지 않는다. 이 모델의 결과는 운용 승인·TC 시퀀스 출력·ROS 전달·송출에 사용할 수 없다.

## 초안과 버전

- 초안은 4-1에서 검증한 패스의 전체 시간창 스냅샷과 현재 비운용 명령 DB의 정수 `version`에 결합된다. 승인된 DB 해시 계약은 4-4 이후 별도로 정한다.
- 모든 초안과 분석 결과는 `non_operational`이며 명령 DB가 `operational: false`, `commands: []`일 때만 편집된다. 초안의 시험 명령 ID는 명령 DB의 실제 항목으로 해석하지 않는다.
- 한 저장소 인스턴스에는 계획 하나와 최대 32개의 불변 리비전, 리비전당 최대 64개 단계가 있다. `expected_revision`이 최신 리비전과 다르거나 패스 시간창·DB 버전이 바뀌면 수정을 거부한다. 저장은 현재 프로세스 메모리에만 적용한다. 영속 저장소·동시 프로세스 간 트랜잭션은 이후 서비스 통합 시 결정한다.
- 단계는 `offset_s`와 `step_id`로 정렬한다. 수정은 추가·교체·삭제이며 충돌이 있는 초안도 보존해 분석할 수 있다.

## 충돌 분석용 합성 속성

| 필드 | 시험 의미 |
|---|---|
| `offset_s`, `duration_s` | 패스 AOS 기준 실행 시작과 소요 초 |
| `resource_mask` | 같은 비트가 동시에 점유되면 자원 충돌 |
| `require_set`, `require_clear` | 앞선 명령들이 만든 상태에 대한 사전 조건 |
| `effect_set`, `effect_clear` | 해당 명령 후의 합성 상태 변화 |
| `uplink_bytes` | 가용 패스 시간의 합성 전송 용량과 비교할 바이트 수 |

분석 프로파일의 `initial_state`, `transfer_rate_bps`, `max_commands`는 시험자가 명시적으로 주입한다. `test_only=1`이 아니면 분석을 거부한다. 전송 용량은 `(LOS - AOS - 앞뒤 여유 시간) × 초당 비트 수 ÷ 8`의 내림값이다. 분석 결과는 여섯 규칙의 위반 비트 집합과 `non_operational=1`만 반환하며 승인 판정을 제공하지 않는다.
