# 단계 5 시험용 TC 경로 계약

이 계약은 TC ICD와 트랜시버 HMAC 사양이 확정되기 전의 소프트웨어 검증용이다. `TEST_ONLY_SEQUENCE`의 합성 명령만 처리하며 실제 TC 패킷·프레임·CLTU, 항우연 연결 및 위성 송출에 사용할 수 없다.

## ROS 검증과 승인

- ROS는 단계 4의 시퀀스·매니페스트를 독립적으로 확인한 뒤 시험 명령 목록을 주입받는다. 명령 존재, 정수 파라미터 범위, 시퀀스 단계·시각 일치, 패스 시간창, 시험용 최근 상태 비트를 각각 검사한다. DB 정수 버전과 시퀀스 해시도 결합한다.
- 일반 명령은 작성자 확인, 주의 명령은 다른 peer, 위험 명령은 다른 lead의 재인증 표시를 요구한다. 승인 시각은 예정 송출 시각을 넘을 수 없다. signer도 승인 상태와 역할·작성자 분리를 다시 검사한다.
- 역할, 재인증, 최근 상태 및 명령 목록은 현재 시험 호출자가 제공한다. 실제 Portal 인증·TM 상태·명령 DB 해시·영속 승인 증거는 연결되지 않았다.

## signer → tc-gate → fake_sat

- signer는 런타임에만 전달된 시험 키로 합성 고정 길이 프레임에 HMAC-SHA256 태그를 붙인다. 키는 저장소·이미지·환경 변수에 넣지 않는다. 이 알고리즘과 프레임은 트랜시버 사양을 뜻하지 않는다.
- 120바이트 시험 프레임은 `PADOTC5!` 8바이트, 시험 버전 1바이트, 위험도 1바이트, 예약 2바이트, 시험 SCID·명령 코드·순번 각 4바이트, 송출·AOS·LOS 각 8바이트, 파라미터·DB 버전 각 4바이트, 시퀀스 SHA-256 32바이트, HMAC-SHA256 32바이트 순서다. 정수는 네트워크 바이트 순서다. 실제 ICD가 확정되면 이 포맷을 운용 포맷으로 변환하지 않고 별도 구현한다.
- tc-gate는 시험 프레임 크기·표식·SCID·DB 버전·패스 시각·ROS 인증 표시·패스당 수량·최소 간격·순번을 검사한다. 게이트 상태는 시험에서 패스별로 새로 만든다. HMAC 키는 게이트에 없다.
- `fake_sat`은 태그를 다시 계산하고 순번 재사용을 거부한 뒤 시험 ACK를 반환한다. 송출 어댑터나 네트워크 소켓은 이 경로에 연결하지 않는다.
- 현재 전체 시험은 한 프로세스의 서로 다른 모듈 호출이다. 실제 `ros-core`/`ros-signer` Unix socket 격리, ROS→DGS-GS mTLS, `kari-adapter` 및 상대 신원 증명은 운용 ICD·키 계약과 배포 경계가 확정된 뒤 연결해야 한다. 호출자가 전달하는 인증 표시는 실제 TLS 인증 결과가 아니다.
